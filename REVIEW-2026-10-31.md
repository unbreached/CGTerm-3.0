# CGTerm 3.0 - Security, Safety and Stability Review (2026-10-31)

Full-codebase audit of the current `color-fonts` tree (~25,000 lines of C).
Six focused reviews covered the whole untrusted-input attack surface: the
transfer protocol parsers, the transfer orchestration layer, the network
and ANSI terminal parsers, the disk-image parser and its new write tools,
the configuration/path/login/clipboard code, and the rendering/menu/UI
lifecycle. Every finding below was re-verified by hand against the source;
line numbers are from this tree.

This review supersedes nothing in `REVIEW-2026-10.md`; it is the next pass.
The known-but-unfixed items from that document are still valid and are not
all repeated here.

## Status: all findings below fixed on 2026-10-31

Every finding in this document (C1, H1-H6, M1-M8 and the LOW list) has been
patched in the working tree. 15 files changed. The tree rebuilds with no
compiler warnings under `-Wall -Wextra -Wshadow -Wpointer-arith`, `make
test` passes, and the disk-image fuzzer runs clean under AddressSanitizer
and UndefinedBehaviorSanitizer on D64, D71 and D81. The Windows-only edits
(config.c `%APPDATA%` fallback, the xfer.c `:` reject) syntax-check under the
MinGW cross compiler; a full Windows link and the GitHub Actions MinGW job
should be confirmed green before release. The original findings are kept
below for the record.

## Baseline / what is healthy

- Clean build with `-Wall -Wextra -Wshadow -Wpointer-arith -Wformat=2`:
  zero compiler warnings (one harmless linker alignment note).
- `make test` passes, including the ZMODEM failure-path and loopback suites.
- The disk-image parser fuzzer ran clean under AddressSanitizer and
  UndefinedBehaviorSanitizer: 2,000 iterations on D64 and 3,000 each on D71
  and D81, no crash. (It exercises the read/parse path only, from a buffer;
  it does not cover `di_load_image`'s file path or the write tools.)
- The June 2026 disk-image hardening is all present and correct: geometry
  validation, block-address clamping, chain-link termination, chain-walk
  caps, the last-block `buflen` underflow clamp, and 16-byte name bounds.
- Path traversal via a hostile ZMODEM filename is defended. The received
  name is sanitized (`multipunter_sanitize_filename`) and then independently
  validated (`xfer_validate_filename`) before any host write; `..`, `/`,
  `\`, NUL, control bytes and Windows device names are blocked, and in batch
  mode a rejected name is dropped rather than written.
- The ANSI/VT parser is clamped at two layers (parameter store and the
  cell-drawing primitives); no out-of-bounds was found despite adversarial
  parameter streams.
- Network robustness is sound: IPv6-with-IPv4-first, SIGPIPE/EAGAIN
  handling, correct 0xFF handling on both Telnet and raw boards.
- The previously reported font double-free on runtime font swap is fixed.
- Two earlier open items are confirmed fixed in the current code: the ESC
  cancel prompt is no longer a modal busy-wait, and the debug/transfer logs
  are per-user, not a shared `/tmp` path.

No remote code execution and no remote memory-corruption primitive was
found. The one memory-corruption bug (C1) is locally triggered through the
UI. The most impactful remote issues are denial-of-service: a hostile or
badly-behaved board can freeze the client.

## CRITICAL

### C1. Column switch leaves `charheight` stale, overflowing the font surface and the dirty-line array
`src/gfx.c:960-1034` (root cause at 974-985; consequences at 120, 146, 179,
207, 727-729, 1034).

`gfx_set_columns()` recomputes `cfg_zoom`, `charwidth`, `gfx_width` and
`gfx_height`, but never reassigns `charheight`. `charheight = 8 * cfg_zoom`
exists only in `gfx_init` and `gfx_set_zoom`. When switching to 80 columns
forces `cfg_zoom` from 1 or 3 to 2, `charheight` stays at its old value (8)
while the font is regenerated at the new zoom:

```c
} else {                         /* going to 80 columns */
  if (cfg_zoom == 1 || cfg_zoom == 3) {
    saved_zoom = cfg_zoom;
    cfg_zoom = 2;                /* zoom changed... */
  }
  charwidth = 4 * cfg_zoom;      /* ...charwidth updated, charheight NOT */
}
```

The regenerated glyph surface is `16 * charheight = 128` px tall, but the
draw loop writes rows up to `15*8 + 7*2 + 1 = 135`: an 8-row heap overflow
of a multi-kilobyte surface (same in `gfx_createfont_ansi`). Separately,
`gfx_menu_lastline = (gfx_height-1)/charheight = (400-1)/8 = 49` instead of
24, so `gfx_vbl` writes `dirty[0..49]` into the static `SDL_bool dirty[25]`
(gfx.c:49), a 25-entry out-of-bounds write.

Trigger, through the normal UI: in 40-column PETSCII mode set zoom to 1 or 3
(Options "Z"), then switch to 80 columns (Options "8", the "G" ANSI toggle,
or opening an ANSI bookmark, which auto-switches at connect). Default zoom
is 2, so a default install is unaffected, but an odd zoom from the Options
panel or a config/bookmark reaches it, and an ANSI board can drive the
switch at connect time.

Fix: set `charheight = 8 * cfg_zoom;` in both branches of
`gfx_set_columns` where `charwidth` is set, and save/restore an
`old_charheight` on the `SDL_SetVideoMode` failure path.

## HIGH

### The transfer-freeze cluster (H1-H4): a hostile board can lock up the client, ESC dead
These four share one root cause and almost certainly explain the
user-reported "it hangs, and drops out to BASIC" during a Frozen Floppy
transfer. Fixing the root cause plus adding per-loop caps resolves all four.

#### H1. `xfer_recv_byte` only polls the keyboard when there is no data (root cause)
`src/xfer.c:690-722`. The cancel/keyboard check runs only inside the
"no data yet" wait branch:

```c
while ((c = net_receive_raw()) == -1) {
  if (timer_get_ticks() > starttime + timeout) return(-1);
  else { timer_delay(1);
         if (timer_get_ticks() > xfer_last_kbd_check + 20) { xfer_check_kbd(); ... } }
}
...
return(c);   /* data path: returns immediately, never polls the keyboard */
```

While a peer keeps bytes flowing with sub-timeout gaps, every call returns a
byte at once and the keyboard is never read. ESC cannot cancel, and any
unbounded read/skip/drain loop in a protocol becomes a hard freeze of the
single-threaded client. Fix: also poll `xfer_check_kbd()` / honor
`xfer_cancel` on a byte-count or wall-clock interval on the data path.

#### H2. ZMODEM `zm_dlread` XON/XOFF skip loop is unbounded
`src/zmodem.c:267, 286`. Both loops drop XON/XOFF (and the high-bit twins)
with `continue` and no counter. A flood of `0x11`/`0x13` after a valid
ZDATA/ZFILE header spins forever; the `ZM_MAX_GARBAGE` cap is upstream of
this path and never applies. Fix: give the loop a bounded garbage budget and
break on cancel.

#### H3. XMODEM `xmodem_fail` / `xmodem_retry` drain loops are unbounded
`src/xmodem.c:79, 87`: `while (xfer_recv_byte(1000) >= 0);` drains "until 1s
of silence" with no byte cap and no cancel check. A continuous flood keeps
`xfer_recv_byte` returning, so the drain never exits. Reachable via the
garbage path (xmodem.c:328) and via the wrong-block/checksum retries
(xmodem.c:244, 254, 271, 278), which additionally `continue` without
incrementing the error counter. Fix: cap the drain (as the start-of-transfer
purge already does at xmodem.c:180) and give the retries a real counter.

#### H4. Rainbow non-SOH scan loops are unbounded
`src/rainbow.c:398-400, 326-327`. During the data phase a flood of any
non-SOH byte makes the `for(;;)` scan spin; the block-0 inner scan has the
same shape and relies on `xfer_cancel`, which is never set under a flood.
Fix: cap the bytes skipped while hunting for SOH and abort past the limit.

### H5. `di_load_image` leaks a file descriptor on every successful load
`src/diskimage.c:631` opens the image; every error path calls
`fclose(file)`, but the success path (around diskimage.c:721) returns the
`DiskImage*` without closing it, and the struct has no `FILE*` field, so the
handle is lost. This is not content-dependent: it leaks on every load.
Browsing a BBS file area opens an image on essentially every interaction, so
descriptors exhaust over a session, `fopen` starts failing, and the
starvation can spill into the socket/modem side. Fix: add `fclose(file);`
before `return(di);`. (The read-path fuzzer misses this because it loads
from a buffer, not via this function.)

### H6. `cfg_set_bookmark_note` can destroy all bookmark notes on a write error
`src/config.c:1138-1142`. The function writes a temp file and renames over
the original, but unlike `cfg_save_setting` it never checks `ferror(tmp)`,
the `fclose` return, or the `rename` return:

```c
fclose(tmp);
#ifdef WINDOWS
remove(notes_path);
#endif
rename(tmppath, notes_path);
```

A disk-full or I/O error mid-write renames a truncated temp over the good
notes file, losing every bookmark's notes and auto-login scripts; on a
`rename` failure the temp is also leaked. Fix: mirror `cfg_save_setting`
(config.c:807-811): check `ferror`/`fclose`, `remove` the temp and return on
error, and check `rename`.

## MEDIUM

### M1. Telnet option negotiation is unbounded: remote UI-freeze plus reply amplification
`src/net.c` `net_telnet_byte` (the `TN_OPT` path, around net.c:447). The
subnegotiation path is capped at 4096 iterations, but option negotiation is
not, and `net_telnet_byte` only returns on a data byte or a drained socket.
A continuous `IAC DO <option>` stream never yields a data byte, so the loop
keeps refilling from `recv` while sending a 3-byte `WONT` per command: the
SDL main loop is starved (window frozen, not closeable) and we flood an
equal volume back at the peer. Fix: add a per-call negotiation-work budget
and return to the caller once it is exceeded.

### M2. `net_write`'s 5-second blocking `select` is reachable from the ANSI parser
`src/net.c:108-110`. `net_write` waits up to 5s for writability. The ANSI
parser calls it to answer DSR/DA queries (ansi.c:803, 806, 836, 940). A
board that floods `ESC[6n` and stops reading fills our send buffer, stalling
the whole loop up to 5s per reply, with SDL unpumped; it is also a secondary
amplification vector. Fix: make the auto-reply send path non-blocking or
throttle generated replies.

### M3. Download write-error path leaks the destination `FILE*` and can leave a truncated file
`src/xfer.c:1378`. `xfer_copy_file` returns 0 on failure, so
`!xfer_copy_file(...)` short-circuits the `||` and `fclose(to)` is never
called; the handle leaks on every mid-download write error. The comment
claims the truncated file is removed, but on Windows `remove` of a
still-open file fails, so it is also left behind. Combined with a disk-fill
batch this trends toward descriptor exhaustion. Fix: close `to`
unconditionally, then test success.

### M4. No aggregate cap on a batch download (disk-fill DoS)
`src/xfer.c:740` plus the Multi Punter / ZMODEM batch loops. The per-file
cap (`XFER_MAX_DOWNLOAD`, 64 MiB) is correct, but `xfer_saved_bytes` resets
per file and nothing bounds the number of files or the batch total. A
malicious board can stream unbounded 64 MiB files and fill the disk; an
unattended/auto-connect session cannot ESC out. Fix: track a batch-cumulative
total and abort past a configurable aggregate limit.

### M5. Punter lost-sync restarts are uncounted
`src/punter.c:191-223`. The late-ACK and "ACKACK"/"CKACKA"/"KACKAC"
detectors `goto restart` without touching `errorcnt`, while only the timeout
and checksum paths are bounded. A crafted repeating pattern loops the block
indefinitely (and the keyboard is unpolled under a flood, per H1). Fix: spend
a restart budget on the lost-sync paths too.

### M6. A comma in a bookmark alias corrupts the bookmark on reload
`src/config.c:393-396` (parse) and `src/config.c:909-914` (save). Aliases
are written raw into a comma-separated line. An alias containing a comma
reparses so the text after the comma is taken as the host, silently
repointing the bookmark to the wrong address. Fix: reject or quote commas in
aliases on save.

### M7. On Windows with `%APPDATA%` unset, per-user files fall back to the current directory
`src/config.c:159-165` (Windows-only). When `APPDATA` is empty the user dir
becomes `"."`, so config, bookmarks, notes and history resolve against the
launch directory again, reintroducing the "lost bookmarks" behaviour the
APPDATA migration was meant to cure. `_mkdir` is unchecked and a pathological
`APPDATA` truncates silently. Fix: fall back to `USERPROFILE\AppData\Roaming`
or `USERPROFILE\CGTerm`, and skip writes if no real directory was
established.

### M8. Font alias redirect leaks the old font (double-free itself is fixed)
`src/menu.c:1850-1857, 1875-1883`. After `menu_font_release`, the redirect
loop repoints aliased slots to the new font; if the released slot was itself
an alias target (a shipped asset failed to load at init), the old font ends
with zero references and is never freed, and body slots can be repointed to
the wrong-sized splash font. Precondition is a missing asset, so impact is
low in a normal install, but it is a leak and a wrong-render. Fix: free
`old` after the redirect if it is no longer referenced; redirect first,
release last.

## LOW

Security / correctness hardening, roughly by value:

- `src/zmodem.c:773` `zm_send_zrpos`: `zm_attn[i] && i < sizeof(zm_attn)`
  tests the index after the dereference (latent 1-byte OOB read, currently
  unreachable because the buffer is always NUL-terminated by the ZSINIT
  handler). Swap the operands.
- `src/diskimage.c:72-80` `di_name_from_rawname` passes `/`, `\`, leading
  `.` through verbatim and writes up to 17 bytes with no size parameter. The
  only extract caller sanitizes in the UI (`ui_term.c`), so it is safe today,
  but the library primitive is unsafe for any future host-path consumer.
  Document the contract or sanitize/length-check in the library.
- `src/xfer.c:1253` `xfer_validate_filename` does not reject `:` (Windows
  alternate data stream / drive-relative) and the reserved-name check misses
  `CONIN$`/`CONOUT$`, `COM0`/`LPT0` and leading-dot stems. Not remotely
  reachable today (names are pre-sanitized), so defense-in-depth.
- `src/xfer.c:201-263` temp files hardcode `/tmp` (ignore `TMPDIR`) and close
  the `mkstemp` fd then reopen by name, a needless TOCTOU window if `/tmp`
  lacks the sticky bit. Use `fdopen` and honor `TMPDIR`.
- `src/config.c:775, 1100` config/notes temp files are a fixed `<file>.tmp`
  opened with `fopen("w")`, which follows a symlink a local attacker could
  pre-place in the user's own config dir.
- `src/config.c:31` `isalnum(*p)` on a plain (possibly negative) `char` is
  UB; `validate_alias` already casts to `unsigned char`. Cast here too.
- `src/login.c:119` `p:N` pause uses an unchecked `strtol` cast to
  `unsigned int`; a huge/negative value from an imported note gives a bogus
  deadline. Clamp it.
- `src/config.c:1053, 1109` a legacy notes line beginning with `[` is read as
  a section header and permanently promoted on re-save (pre-fix files only).
- `src/diskimage.c:336-346` `blocks_free` counts the reserved D71 track 53,
  so a crafted BAM inflates the reported free count (display only; allocation
  correctly skips track 53).
- `src/xfer.c:1029, 1546, 1719` upload size via `(int)ftell` truncates a
  local file over 2 GiB (local input only).
- `src/ui_edit.c:267-275` the cgedit rectangle `SWAP` can write a stale
  80-column `rect_x` into `gfx_cursx` after a switch to 40 columns, past the
  live-window clamp (convoluted multi-step trigger).
- `src/gfx.c:546` `gfx_savescreen`'s `converted[80*3+1]` has zero margin;
  correct only while columns stay <= 80. Size it from `cfg_columns`.
- `src/menu.c:1854-1856, 1879-1881` the font redirect loop compares against a
  pointer that may already have been freed (no deref; technically UB).
- `src/config.c` and `src/session.c` do not NULL-check `localtime` (never
  fails in practice).

Carried over from `REVIEW-2026-10.md` and still open: alias truncated to 27
chars by `addhost` while the editor allows 63; notes longer than the read
buffer split with spurious newlines; the system `/etc/cgterm.cfg` stops being
read once `~/.cgtermrc` exists; F2 "save path" appends a raw `dldir =` with
`fopen("a")`; `install-macos.sh` / installer path disagreements; directory
listings bubble-sorted on every read.

## Recommended fix order

1. C1 (gfx `charheight`) — a one-line omission with a heap overflow; fix
   first.
2. H1-H4 as one change: make the transfer receive path cancellable and bound
   every skip/drain loop. This closes the remote freeze and most likely the
   Frozen Floppy symptom.
3. H5 (`di_load_image` fclose) and H6 (notes-file atomic write) — one-liners,
   real data-loss / resource-exhaustion.
4. M1-M2 (telnet and ANSI-reply DoS), then M3-M8.
5. The LOW set as a hardening sweep.

Each of these is small and local. After anything touching the Windows
`#ifdef` paths or the Makefile (M7 especially), cross-compile with
`scripts/cross-compile-win.sh` and keep CI green on all three platforms, per
the project's cross-platform rule.

## Feature ideas to discuss

Grouped; several double as hardening. These are for discussion, not a
commitment.

**Transfer and session**
1. Finish transfer auto-detection: ZMODEM auto-start already works; add
   detection of the Punter "GOO" / Multi Punter / XMODEM start sentinels so
   any download offers or starts the right receive.
2. A single bounded, cancellable transfer I/O primitive (the clean form of
   the H1-H4 fix), with a visible "press ESC to abort" that always works even
   under a byte flood.
3. Resume and verify: ZMODEM crash-recovery resume on the receive side, plus
   an optional SHA-256/CRC display of each completed download.
4. Transfer history viewer with re-run, and per-file batch results surfaced
   in the UI (a failed file in a Multi Punter batch is currently quiet).

**Connectivity**
5. TLS / telnets and dual-stack host fallback, since more boards sit behind
   TLS front-ends. (Still open from earlier passes.)
6. A BBS-list import (for example the telnet BBS guide) into bookmarks, with
   search, reorder and quick-dial beyond slots 0-9.
7. A small on-connect scripting layer beyond expect/send: conditional steps,
   "go to the file area", a named macro per bookmark.

**Disk tools**
8. Image-to-image copy, "put a whole folder into a new D64", 40-track D64,
   GEOS/VLIR detection, and correct D81 REL super-side-sector handling (the
   current linear walk mis-accounts those blocks, M-level).
9. PETSCII-accurate names in listings rendered with the C64 font, and a
   SEQ/PRG viewer with PETSCII rendering and screenshot-to-PNG.

**Platform and packaging**
10. macOS notarization and a signed installer (removes the "Open Anyway"
    step), a Linux `.desktop` file and man page, and the native MinGW build
    wired into CI alongside `make test` and the fuzzers.
11. Add fuzz targets for the ANSI parser and the Telnet negotiation state
    machine, and extend the disk fuzzer to the `di_load_image` file path and
    the write tools (validate/lock/rename/extract/insert), which this review
    could only check by hand.

**Robustness as a feature**
12. Atomic, checked writes for every config/bookmark/notes/history file
    (generalizes the H6 fix), with escaping of delimiters so any alias or
    note round-trips.
