# CGTerm 3.0.4 - Project Review and Priority List (2026-11-15)

Whole-project review of the `color-fonts` tree at commit `98995b4`
(about 26,000 lines of C). Scope: stability, security, transfer protocols,
graphics, keyboard, UX, new features, build, tests, packaging and release
process.

**Nothing was changed.** This document only records findings and ranks
them. It is the next pass after `REVIEW-2026-10-31.md`; items fixed there
are not repeated.

## Status after the fix pass (2026-11-15, working tree, not committed)

A fix pass followed this review. Version is now 3.0.5 in the source.
Verified: native build with zero compiler warnings, `make test` passing
(with new Rainbow, noisy Punter download and XMODEM start tests), the
transfer suite clean under ASan/UBSan, the 32-bit Windows cross-build
clean, and a startup run with a deliberately broken config. Not verified:
anything that needs a real board, a real keyboard layout other than the
build machine's, or a Windows machine.

**Fixed:** P0-1, P0-4, P0-5, P0-7, P1-1, P1-2, P1-3, P1-4, P1-5, P1-6,
P1-7, P1-8, P1-12, and from P2: P2-1 (send side), P2-3, P2-4, P2-6 (reply
flooding), P2-7, P2-13 (overlay and ANSI copy), P2-14, P2-15, P2-12 (idle
loop), P2-16 (hardening flags, sanitizer target, CI jobs, dead Makefile

**Partly fixed:**

  libraries still require the build machine's macOS. Running on older
  macOS needs those libraries built from source with a deployment target.
  Still Apple Silicon only (READMEs corrected to say so).
- P0-6 Windows: the executables now have stack protector, ASLR and DEP,
  downloads are checksum-pinned, and the unused MPEG/FLAC DLLs are gone.
  SDL.dll, SDL_mixer.dll, libmikmod, ogg and vorbis are still the 2012
  builds.
- P1-9 tests: Rainbow, noisy Punter download and XMODEM start are
  covered. Telnet, config, keyboard-profile and login parsers still have
  no tests, and there is no fuzzer for the network-facing parsers.
- P1-10 release: version single-sourced, `make dist-src` and
  `make checksums` added, CI builds the real Windows package. Unversioned
  asset names, signing/notarization, the website HTTPS problem, the
  draft v3.0.1 release and the default-branch name are untouched.
- P1-11 docs: false claims corrected in README and README.md, README.txt
  and CHANGELOG updated. The three READMEs are still separate files.

**Not done, on purpose or for lack of a way to test:**

- P0-3 demo fonts: needs your decision.
- Punter: sending a cancel to the board (no cancel signal is defined in
  the protocol code we have), and rejecting a short non-final block (risk
  of breaking a board that ends a file that way).
- XMODEM receive: confirming a single CAN or EOT, and the 0x1A padding
  trim; both are protocol ambiguities where a stricter rule can break

- P2-5 per-byte upload writes: the socket does not set TCP_NODELAY, so
  the kernel already coalesces them; not worth the risk of a missed flush.
- Rainbow upload header size field (bytes vs block count): no evidence
  which one boards expect.
- Telnet binary mode / CR NUL stripping.
- P2-8/P2-9/P2-10 keyboard profiles (positional mode, per-user profile
  directory, paste in input dialogs, RESTORE key). The profile doc now
  states what a profile really controls.
- P2-11 font atlas redesign, redraw loops in the bookmark editor, PNG
  screenshots, `-Wextra` triage, removing stray tracked files.
- All of P3 (new features).

## Second fix pass (2026-11-16, version 3.0.8)

Released in between: 3.0.5, 3.0.6 (C*Base alignment), 3.0.7 (ANSI start
screen). This pass closed most of what the first one left.

**Now fixed:**

- P0-3 fonts: the five fonts with restrictive licences are removed;

- P2-2 Punter: C*Base has no cancel sequence at all (it frees itself

- P2-1 XMODEM receive: stray single CAN ignored; padding follows C*Base.
- P2-6: C*Base's modem driver is 8-bit transparent (no IAC, CR or NUL

  for it.
- P2-9 per-user keyboard profile folder; P2-10 paste in input dialogs;
  P2-13 PNG screenshots; P2-17 stray tracked files removed; P3-8
  transfer percentage and time left.

  remaining `-Wextra` output (missing initializers, shadowed parameter
  names, sign compares between values that are never negative) was
  looked at and holds no defect.

**Still open, and why:**

- XMODEM receive keeps accepting a single EOT, and does not strip 0x00
  padding: both stricter rules lose data in the common case (C64 program
  files end in 0x00 bytes).
- Rainbow upload header size field: C*Base 3.1 has no Rainbow code, so
  there is still no reference to check against.
- P2-5 per-byte upload writes: unchanged, the kernel coalesces them.
- P0-2 macOS: still needs macOS 26 and Apple Silicon. Fixing it means

  machine with an older macOS to prove it.
- P0-6 Windows: SDL.dll, SDL_mixer.dll and its codec DLLs are still the

- Notarization needs an Apple Developer ID.
- P2-8 positional keyboard mode, P2-11 font atlas redesign, the redraw
  loops in the bookmark editor, a RESTORE key.
- P3 new features other than P3-8.

## How this was done

Four read-only passes covered the tree: (1) network, parsers, config and
file handling, (2) the transfer protocols, (3) graphics, UI and keyboard,
(4) build, tests, packaging and release process. `make test` and
`make fuzz` were run; the app itself was not driven.

Verification status is marked on each item:

- **[checked]** - I re-read the cited lines or re-ran the command myself
  after the pass reported it.
- **[read]** - found by reading the code in the pass, not independently
  re-checked. Treat line numbers as accurate but confirm before fixing.
- **[plausible]** - the code path is real, but the trigger depends on
  board or OS behaviour nobody has reproduced.

Effort: S = under a day, M = a few days, L = a week or more.

## Baseline: what is healthy

- `make test` passes: four suites, 0 failures, about 6 s including
  compile. `make fuzz` (disk images, ASan + UBSan) runs clean.
- Default build (`-O2 -Wall`) has zero compiler warnings.
- No Critical or High memory-safety finding in this pass. The ANSI parser
  (cursor, scroll region, parameter counts), disk-image chain walking and
  BAM indexing, `kernal.c`, `paths.c`, CRC code, ZMODEM subpacket bounds,
  Punter block-length clamp, download size caps and remote-filename
  traversal handling all held up under tracing.
- CI exists (`.github/workflows/build.yml`: Linux, macOS, MSYS2) and is
  green.
- Native builds already get `-fstack-protector-strong`,
  `-D_FORTIFY_SOURCE=2` and PIE.

| ID | Area | Item | Effort | Status |

| P0-2 | Packaging | macOS app only runs on macOS 26 | S-M | checked |
| P0-3 | Licensing | Personal-use demo fonts shipped in a BSD project | M | checked |
| P0-4 | Protocol | Raw PETSCII board mistaken for telnet, corrupts transfers | S-M | checked |
| P0-5 | Protocol | Punter download still uses the rigid 3-byte handshake read | S | checked |
| P0-6 | Packaging | Windows: 2012 DLLs without ASLR/DEP, exe built without hardening | M | partly checked |

**P0-1. Rainbow upload retry is broken.** `src/rainbow.c:141-143`.
`rainbow_send_block` runs `while (len-- > 0) xfer_send_byte(*data++);`
inside its retry loop, consuming its own parameters. After the first
attempt `len` is -1 and `data` points past the payload, so every retry
(NAK, GOO, timeout or "unexpected reply") sends length byte 0xFF with a
valid complement and no data. A clean first-attempt upload works, which is
why it works on a quiet board; one retry and the upload is unrecoverable.
This is the most likely cause of the Rainbow half of Larry's report, and
it corrects the earlier conclusion that Rainbow had no concrete bug.
Related, same function: only one byte is read after each block
(`rainbow.c:148-166`), so a single stray status byte forces a retry and
therefore hits this bug. There is no Rainbow test at all (see P1-9).

**P0-2. macOS package targets macOS 26 only.** `otool -l` on the shipped
`CGTerm`, `cgchat` and `cgedit` binaries shows `minos 26.0`, while
`scripts/package-macos.sh:52` declares `LSMinimumSystemVersion 11.0`. No
deployment target is set anywhere in the Makefile or scripts, and the
bundled Homebrew dylibs are built for the host OS. Users on macOS 15 or
older get an app that will not launch. The package is also arm64 only,
while `README.md:63` and `README:199` claim "arm64 + x86_64" [read].

**P0-3. Demo fonts with a personal-use licence.** The repo and source
tarball track `assets/NanoPixDEMO-Regular.ttf`,
`assets/Maesto-Regular_demo.otf`, their zips, and `.bmp` grids derived
from them. `assets/1001fonts-nano-pix-demo-eula.txt` is a "Free For
Personal Use" licence whose section 4 says the font "may not be modified,
altered, adapted or built upon". `LICENSE:41-42` only says media "may
carry their own licenses". This needs a decision from you: get
permission, replace the fonts, or remove them. The licence of
`assets/cgterm.xm` is also not stated, and the binary packages carry no
third-party licence texts for SDL (LGPL), libmikmod (LGPL), mpg123,
ogg/vorbis, FLAC [read].

**P0-4. Telnet auto-detection misfires on PETSCII art.**
`src/net.c:436-443`. On a raw (non-telnet) board, PETSCII pi (0xFF)
followed by a graphics byte 0xFB-0xFE latches `net_telnet_seen = 1` for
the whole session. From then on outgoing 0xFF is doubled and incoming
0xFF pairs are eaten, so every Punter/XMODEM block containing 0xFF fails
its checksum. 0xFF followed by 0xFA is treated as a subnegotiation start
and swallows everything up to 4096 bytes, then disconnects. Suggested
direction: make telnet a per-bookmark setting, or only honour IAC during
the first bytes of a PETSCII session.

**P0-5. Punter download handshake.** `src/punter.c:41-112`. 3.0.4 fixed
the upload side; the download side still reads fixed 3-byte groups in
`punter_recv_string` / `punter_handshake`. Rotation recovery exists only
for `ACK`, not for `SYN` or `S/B`, so one stray byte before either can
fail a download with "Handshake timeout" [plausible on real boards]. The
noisy test added in 3.0.4 covers upload only.

**P0-6. Windows package.** `scripts/cross-compile-win.sh:68` builds with
`-O2 -Wall -DWINDOWS` only, so the released exe has none of the stack
protector / FORTIFY flags the Makefile applies [checked]. The bundled
`SDL.dll`, `SDL_mixer.dll`, libmikmod, FLAC, ogg, vorbis and smpeg DLLs
date from 2012 and are reported to have no ASLR/DEP flags [read]. The
script also downloads the SDL dev archives into predictable `/tmp` paths
with no checksum [read]. smpeg and FLAC are not needed for XM playback
and could be dropped.

**P0-7. Paste queue survives a disconnect.** `clipboard_paste_clear()` is
only called from the ESC key (`src/keyboard.c:450`). If a board drops the
link while an auto-login `s:` step or a paste is draining, the remaining
bytes (for example the tail of a password) are sent to whatever connects
next, including the automatic redial. Clear the queue and abort the login
script inside `net_disconnect()` and `net_connect()`.

| P1-4 | Input | Paste, macros and auto-login are case-swapped in ANSI mode | S | checked |
| P1-5 | Keyboard | AltGr is treated as the Commodore key | S | checked |
| P1-6 | Graphics | ANSI glyphs half height at zoom 4 | S | checked |

| P1-8 | Protocol | Rainbow receive does not drain a bad block | S | read |
| P1-9 | Tests | No tests for Rainbow, telnet, config, keyboard profiles, login | M-L | read |

**P1-1. ZMODEM auto-start.** `src/session.c:160-176`, default on. It
fires on the 6-byte pattern `**\x18B00` anywhere in terminal output,
PETSCII mode included, then saves remote-named files without asking. Any
user who can post those bytes in a message base triggers it for every
CGTerm reader. Existing files are not overwritten and there are per-file
(64 MiB) and per-batch (1 GiB) caps, but the batch counter resets on each
receive (`xfer.c:826`), so repeated triggers can fill the disk
unattended. Suggested: require a full valid ZRQINIT header, confirm the
first auto-start per session, add a per-session byte budget. Related low
items: leading-dot names such as `.profile` are accepted; the Windows
reserved-name check misses `CON .txt`; the overwrite guard is a probe
then `fopen("wb")`, not an exclusive create.

**P1-2. Plaintext credentials.** `login=` lines live in `~/.cgterm-notes`,
created with plain `fopen("w")`; there is no `chmod` or `umask` call
anywhere in `src/`. On a default umask the file is world-readable, and
every edit recreates it. Capture logs have the same problem and contain
typed passwords when local echo is on. Create these files 0600, or move
secrets to the OS keychain.

**P1-3. Config can lock the user out.** `cfg_save_setting()` writes lines
of any length (`src/config.c:505`), but `cfg_readconfig()` treats a line
of 255+ characters as fatal (`config.c:791-795`) and `main` exits. A long
macro or a long download-directory path is enough. Same family: any
unknown key or out-of-range value aborts startup, including uncommenting
the shipped template line `#reconnect = 0` (rejected because the check is
`<= 0`, `config.c:660`). All of these print to stdout only, which a
Finder or Explorer launch never shows. Warn and skip instead of exiting,
and show errors on screen.

**P1-4. ANSI-mode case swap.** `src/clipboard.c:32-38` always applies the
PETSCII letter-case swap. On an ANSI board, paste, macros and the
auto-login step `s:Secret` are sent as `sECRET`, so logins fail.

**P1-5. AltGr.** `src/keyboard.c:571` uses `KMOD_ALT`, which includes
right Alt, and the Commodore column is consulted before unicode
(`keyboard.c:618`). On Swedish and German layouts AltGr+2 sends a colour
code instead of `@`, AltGr+8 a colour code instead of `[`. Restrict C= to
left Alt, or prefer unicode when it is printable. Related: Caps Lock
counts as Shift for special keys (`keyboard.c:569`), so Return sends
0x8D and Home clears the screen.

**P1-6. ANSI font has no vertical zoom.** `src/gfx.c:203-204` copies the
16 source rows 1:1 while only the horizontal axis is zoomed. Correct at
zoom 2 only; at zoom 4 glyphs fill the top half of each cell and box art
does not join.

**P1-7. Zoom 8.** Config accepts zoom 1-8 (`config.c:653`) but a 40-column
zoom-8 font atlas is 16384 px wide, which SDL 1.2 refuses; the NULL
result is not checked. The Options menu only cycles 1-4, so the range is
inconsistent. Cap at 7 or lay the atlas out as a grid. The cursor in ANSI
mode also blinks by XOR 0x80, which selects a different CP437 glyph
instead of a block (`gfx.c:404-407`).

**P1-8. Rainbow receive.** `src/rainbow.c:214-261`. On a header, EOD or
checksum error it replies without draining the rest of the in-flight
block, so leftover payload is parsed as control bytes: a payload 0xA1
ends the transfer as a success with a truncated file.

**P1-9. Test coverage.** Covered: diskimage, dir, xmodem, punter, xfer,
zmodem, crc, ansi. Not covered at all: `rainbow.c`, `net.c` (telnet),
`config.c`, `keyboard.c` (.kbd parser), `login.c`, and the UI. A single
NAK-once Rainbow send test would have caught P0-1. Also missing: noisy
Punter download, Multi Punter receive, XMODEM-1K, 0xFF-in-payload through
the telnet layer, hostile filenames. The only fuzzer covers disk images
with a fixed seed; the network-facing parsers (ANSI, telnet, ZMODEM
headers) have none. `make test` runs without sanitizers.

**P1-10. Release process.**
- "3.0.4" is hand-maintained in `src/cgterm.c`, `package-macos.sh` and
  the `.nsi`; the modem screen still prints "cgterm 3.1" / "v3.1"
  (`src/modem.c:410,427`) [checked]. Single-source it from a `VERSION`
  file.
- Asset names carry no version, and 3.0.2 and 3.0.3 were rebuilt in
  place after release. Users and caches cannot tell builds apart. This
  was a deliberate choice earlier (names match the site links); worth
  revisiting, for example versioned assets plus stable "latest" links.
- No `SHA256SUMS` asset, no signatures; the website serves downloads over
  plain HTTP because HTTPS shows a self-signed placeholder.
- Releases are built by hand on one Mac; no script creates the source
  tarball. CI does not build the i686 Windows package that actually
  ships, runs no sanitizer job, and has no release job.
- macOS package is ad-hoc signed, not Developer ID signed or notarized;
  "signed" in the release notes overstates it.
- The v3.0.1 release is still a draft; default branch is `color-fonts`
  with `main` 38 commits behind; GitHub shows the licence as "Other".

**P1-11. Docs.** `README` (shipped in the Windows zip) lacks the
3.0.3/3.0.4 notes and still says music uses SDL_mixer. `README.txt`
carries the patch log but ships in no binary package. `README.md` is the
GitHub page. Pick one canonical source. `MUSIC-IMPLEMENTATION.md` is
obsolete. The README TODO "connection status" is already done (the status
line shows host, redial countdown, mode, capture, clock).
`assets/KEYBOARD-PROFILES.md` promises a positional C64 feel that the
unicode-first input path no longer delivers (see P2-8).

**P1-12. Blocking DNS.** `src/net.c:298` calls `getaddrinfo()` on the UI
thread with no event pump and no ESC. A slow resolver freezes the window,
and with auto-redial it repeats on every attempt.

### P2 - Improvements (quality, polish, smaller bugs)

Stability and protocol:

- **P2-1.** XMODEM send does not purge NAKs queued while the user picks a
  file, and can run ahead of the receiver (`xmodem.c:404-428`). EOT ACK is
  never checked; a single stray CAN aborts and a single EOT completes
  (`xmodem.c:242-244, 511-520`). [read]
- **P2-2.** Punter: user cancel sends nothing to the board, which keeps
  retrying into the terminal (`punter.c:397-401`). A short block with a
  non-final block number is saved as a successful, truncated file
  (`punter.c:394-416`). [read]
- **P2-3.** Multi Punter: the announcement wait has no overall timeout
  (`xfer.c:428-470`); send blocks for 4.5 s per file with no key polling
  (`xfer.c:1652-1657`). [read]
- **P2-4.** ZMODEM: a skipped file is counted as sent (`xfer.c:1778`); a
  peer streaming empty subpackets holds the client in transfer mode
  (`zmodem.c:920-951`). [read]
- **P2-5.** Uploads write one `send()` per byte; slow and packet-heavy
  for ZMODEM and 1K blocks. Buffer per block. [read]
- **P2-6.** Telnet: replies are not state-tracked per option, so a peer
  can flood NAWS/TTYPE requests (`net.c:458-519`); binary mode is never
  requested and CR NUL is not stripped. [read]
- **P2-7.** Scrollback: PageUp/PageDown move one line, nothing snaps back
  to live on new output, no position indicator, and a 40/80 switch leaves
  old history wrapped at the wrong width (`ui.c:647-658`). [read]

Keyboard and input:

- **P2-8.** With unicode-first input the unshifted and shifted `.kbd`
  columns are effectively dead in PETSCII mode: profiles cannot remap
  RUN/STOP, HOME or DEL, and shifted C64 graphics cannot be typed. Add a
  per-profile "positional" mode or correct the docs. [read]
- **P2-9.** Profiles are found only in the asset directory (inside the
  .app or Program Files), capped at 20, and store raw SDL 1.2 key
  numbers. Add a per-user directory. [read]
- **P2-10.** Input dialogs are ASCII only with no paste, so a hostname
  cannot be pasted. Ctrl+V is always paste, so 0x16 cannot be sent. No
  RESTORE equivalent; Shift+Backspace does not give INST. Auto-login
  steps split on `;` with no escape, so a password containing `;` is
  cut. [read]

Graphics and UI:

- **P2-11.** Three colour-expanded font atlases (16 MB each at zoom 4)
  are rebuilt on every colour, zoom or charset change. Tinting a 1-bit
  glyph set at draw time removes the cost and the zoom limit. [read]
- **P2-12.** Idle loop wakes every 1 ms (`cgterm.c:508`); the bookmark
  editor and keyboard test redraw the whole menu every 20 ms with no
  input. Laptop battery cost. [read]
- **P2-13.** Screenshot from the menu includes the menu overlay; BMP
  only. "Copy screen" in ANSI mode turns box characters into letters and
  ignores scrollback. [read]
- **P2-14.** Window close and a failed fullscreen toggle call `exit(1)`;
  Q quits without confirmation while connected. [read]
- **P2-15.** Bookmarks with `:` or `_` in the host (IPv6, some
  hostnames) are written but silently dropped on the next start
  (`config.c:403-407`). History stops updating after 4096 entries. On
  Windows, socket errors show "No error". [read]

Build:

- **P2-16.** Add `-Wextra -Wshadow -Wformat=2` (currently about 50
  warnings, mostly initializers; the sign-compare ones deserve a look),
  full RELRO and `-z noexecstack` on Linux, a `make asan` target, and run
  tests under ASan/UBSan in CI. Remove the dead `HAVE_SDL_MIXER` Makefile
  block that prints a misleading "music support disabled". [read]
- **P2-17.** Repo hygiene: `assets/kbd-backup/` (including a screenshot),
  duplicate 1.5 MB BMPs in `assets/` and `assets/fonts/`, font zips, and
  the review documents all end up in the source tarball. A
  `.gitattributes` with `export-ignore` fixes the tarball. Add
  `SECURITY.md` and issue templates. [read]

**P3-3. What the SDL2 port involves.** Judged from actual API use:

- Unchanged: software surface drawing (about 200 calls), audio, timing.
- Mechanical: about 14 renamed surface calls.
- Video: 6 `SDL_SetVideoMode` sites and 16 `SDL_UpdateRect` calls become
  one window, one renderer and one streaming texture. Confined to
  `gfx.c` and `modem.c`.
- Input is the real work: 28 event loops in 9 files, 17 reads of
  `keysym.unicode` (becomes a separate text-input event), 358 `SDLK_`
  references, and `.kbd` files that store SDL 1.2 key numbers and need a
  translation table.

What it buys: proper integer/letterboxed scaling and fullscreen (P3-5),
HiDPI, vsync, native clipboard instead of `popen`, dead keys and IME,
mouse wheel, drag-and-drop upload, the end of the font-atlas limits
(P1-7, P2-11), and no sdl12-compat to bundle, which also simplifies P0-2
